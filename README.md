# 記事・ライトノベル読み上げ（TTS）市場 調査レポート

**調査日:** 2026年8月16日
**調査方法:** 11本の調査エージェントによる並列Web調査

---

## 0. 出発点となった問い

> 移動中にイヤホンで記事を読みたい。ながら歩きは危ないので、読み聞かせのように読んでくれるアプリは存在するか。
> 応用として、記事を耳で聴ける形にしたり、ライトノベルの文章を読んでくれるものがあれば需要があるのではないか。

この問いを11の観点に分解して調査した。結論を先に書く。

---

## 1. 結論（3行）

1. **存在する。しかも既にスマホの標準機能で無料でできる。** iOS Safari の「ページの読み上げを聞く」、Android Chrome の「このページを読み上げ」が、本文だけ抽出＋画面ロック中も再生継続に対応済み。まず今日これを試すのが最短。
2. **プロダクトとしての市場は「ある」が、そこから金を取る手段が壊れている。** 先行最大手 Speechify はユーザー5,000万人に対して ARR 約$17.6M（推定課金率0.3%程度）。人力ナレーション型は全滅、NYT ですら単体音声アプリを畳んだ。
3. **ただし日本語とライトノベルには明確な空白がある。** 主要プラットフォーマーのAIナレーションは全て日本語非対応。ラノベは規約上クリーンな読み上げ経路が10年以上存在しない。ここが唯一の狙い目だが、同時に法務の地雷原でもある。

## 2. 「今すぐ使える」現実解

### 追加アプリなしでできること（無料）

| 手段 | 本文だけ読むか | バックグラウンド/ロック | 総合 |
|---|---|---|---|
| **iOS Safari「ページの読み上げを聞く」** | ◎ リーダー抽出＝本文のみ | ◎ ロック画面制御・AirPods対応 | **◎** |
| **Android Chrome「このページを読み上げ」** | ○ 対応ページのみ | ◎ バックグラウンド・ロック対応 | **◎** |
| Edge Read Aloud（没入型リーダー併用） | ◎ | ？ モバイルの継続は未確認 | ○ |
| iOS 画面の読み上げ | △ UIも読む | △ | △ |
| Android 選択して読み上げ | △ 手動選択 | △ 実験的機能 | △ |
| TalkBack | × UI全読み | — | × |
| Web Speech API 直接 | — | × iOSはロックで停止 | × |

**最短ルート**

- **iPhone**: Safariで記事を開き「ぁあ」→「ページの読み上げを聞く」。設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 日本語 で **Siriの声、または Kyoko/Otoya の拡張版をダウンロード**しておくと品質が上がる。
- **Android**: Chrome の3点メニュー →「このページを読み上げ」。日本語音声は「雲」（女性）「川」（男性）。
- **PCでの長文**: Edge の没入型リーダー + Read Aloud（Natural Voices）が音質面で最良。

### 標準機能で足りなくなる境界線

1. リーダー／読み上げ非対応ページ（SPA、独自レイアウト、掲示板、検索結果）
2. 複数記事をキューに溜めて連続再生したい（標準機能は「今開いている1ページ」のみ）
3. オフラインで聴きたい（Chromeの高品質音声もEdgeのNatural Voicesもオンライン依存）
4. 音声ファイルとして書き出したい／SSMLで細かく制御したい
5. PDF・EPUB・自炊テキストも同じ体験で聴きたい
6. 音声品質そのものへの不満（Kyoko/Otoya は旧世代で長時間聴くと疲れる）

### 有料アプリのベスト3（日本語記事を通勤中に聴く用途）

| 順位 | 製品 | 料金 | 決め手 |
|---|---|---|---|
| 1 | **Instapaper** | Premium $5.99/月・$59.99/年 | 2026年3月にAI Voices投入（**8言語17音声に日本語を含む**）、7月にAndroidへも展開。**Playlist（連続再生キュー）＋フローティングプレイヤー**で歩きながら聴く設計が最も明確 |
| 2 | **Voicepaper**（日本製） | 無料＋Plus課金 | UI・サポートが日本語。Web記事/PDF/EPUB/画像OCR対応。「通勤中のながら読書」を製品として想定。無料枠は30分再生→5時間待機なので実質Plus前提 |
| 3 | **Speech Central** | 買い切り $9.99/プラットフォーム | **RSS → 連続音声再生**を正面から実装。iOS/Android/Win/Mac全対応。サブスクではない |

補欠: **ElevenReader**（音声品質は断トツだがキューが弱く無料枠が小さい）、**Chrome標準機能**（ゼロコスト解）。

### 重要な前提変化

**Pocket は2025年7月8日にサービス終了**（データは10月8日完全削除）。読み上げ機能を持つ無料の定番が消滅し、この分野は2025〜2026年に再編中。受け皿は Matter 年$79.99、Instapaper Premium 年$59.99 など有料のみ。

## 3. ライトノベル・Web小説 — 最も穴が大きい領域

### 現状

- **なろう公式は本文の機械的取得を規約で明確に禁止**。ヘルプ「アプリ・Webサイトの開発・運営にあたっての注意点」で「掲載作品の本文を機械的に取得してアプリやWebサイトで表示／ダウンロードする行為」を**禁止例として名指し**。
- **公式「なろう小説API」は本文を返さない**（タイトル・あらすじ・ランキング等のメタデータのみ）。
- **カクヨム公式アプリにTTS機能なし**。作者自身が「iPhoneの読み上げ機能で1ページずつ読ませている」と紹介する状況。
- 結果、受け皿は個人開発のWebView型アプリ（「小説を聞こう」「ことせかい」など）と、ブラウザ拡張のみ。全てグレー。

### 実ユーザーの不満

最大の不満は音声の自然さではなく **固有名詞の誤読**。実例:

> 「奴は扉の隙間から覗いている私に気づいた」
> → 「**ヤッコ**は扉の**スキカン**から覗いている**シ**に気づいた」

次いでアプリの安定性（レビュー中バグ・不具合系の言及が63%）、サイト仕様変更による破損。「サイトの仕様変更に素早く対応している」がアプリの褒め言葉になっている＝**スクレイピング依存の構造的脆弱性が常態化**している。

### 商業ラノベ

BOOK☆WALKER はラノベ約1万冊読み放題なのに、音声版は紹介記事が「20〜60選」で成立する規模。Kindleで買ったラノベも権利設定・固定レイアウトでTTSが無効化されうる。**シリーズを1巻から最新刊まで音声で追い切ることが、公式・非公式どちらの経路でも成立しない。**

### 空いている穴

1. **作品単位の共有読み辞書が存在しない** — 対策は各アプリのローカル辞書止まり。同じ作品を聴く数千人が、それぞれ手作業で同じキャラ名・造語を登録し直している。**作者本人が正しい読みを登録できる仕組みは誰も作っていない。**
2. **権利的にクリーンな公式読み上げ経路が誰にも用意されていない** — プラットフォーム側が読み上げ用テキストAPIか公式再生ボタンを1つ出すだけで解ける問題が10年以上放置。副作用として作者は無断YouTube音声化に晒され、正規に聴きたいユーザーには正当な手段がないという最悪の均衡。
3. **多話者（キャラ別音声）× 連載Web小説の自動化が繋がっていない** — 話者を分けるAIは既にあるが全て「貼る／上げる」型。技術的な未解決点は日本語のカギ括弧セリフに対する**話者推定**。
4. **連載更新のポッドキャスト化が存在しない** — ブックマーク作品の更新検知→音声生成→フィード配信をやっているものが一つもない。
5. **継続性リスク** — 主要ツールが全て個人開発で、サイト仕様変更のたびに壊れる。

## 4. 日本語という壁

### プラットフォーマーのAIナレーションは全て日本語非対応

| サービス | 対応言語 | 日本語 |
|---|---|---|
| Amazon KDP Virtual Voice | 英・西・仏・伊（米国市場のみ、招待制ベータ） | ✕ |
| Audible AIナレーション（出版社向け） | 英・西・仏・伊 | ✕ |
| Apple Books デジタルナレーション | 英語のみ | ✕ |
| Google Play ブックス 自動ナレーション | 英・西・独・仏・ヒンディー・ブラジル葡 | ✕ |
| Spotify × ElevenLabs | 英語中心＋10言語追加 | ✕ |

国内で日本語AIナレーションを実装しているのはオトバンク（カタリテ、AI本人オーディオブック）のみで、しかも自社カタログ限定。

### 技術的ボトルネックは音声品質ではなくG2P（漢字の読み分け）

- デモ音声は完璧に聞こえるが、長文になると誤読が顕在化する構造的ギャップ。
- 「金＝きん/かね」のように**分野・文脈で音訓が切り替わる語**が最も精度が落ちる。
- 日本語は高低アクセント言語で、読みが正しくてもアクセント核が違うと不自然になる（G2Pとは別課題）。
- 助数詞（1本/1枚/1匹）の読み分けも独立した難所。
- **2025〜2026年にようやくベンチマークが立ち上がった段階**（ja-tts-g2p-bench、JKYB-Parakeet、YOMI-Bench）。裏返せば、それ以前は横並び比較の物差しすら無かった。

### 日本のニュース音声化は「全文」ではなく「抜粋」に留まっている

| サービス | 方式 |
|---|---|
| 朝日新聞アルキキ | **記事の前文（第1段落）のみ**を音声合成。有料版は月240円 |
| 聴く日経 | 日経朝刊から**約16本を厳選**して読み上げ、平日朝夕 |
| NewsPicks AI記事読み上げ | 全記事ではなく一定時期以降・よく読まれる記事に限定。**理由は生成コスト**と明記 |

**日本語ニュースの全文読み上げを高品質で回しているサービスは確認できなかった。**

参考として朝日新聞は、独自の読み上げ辞書を構築し、**新聞記事文をテレビ放送原稿に近い形式へ自動変換**して誤読・アクセントの不自然さを潰している。これが日本市場の現実解だが、自社専用資産であり、**共有可能な日本語読み辞書のインフラは存在しない。**

### 日本の市場規模

| 指標 | 数値 | 備考 |
|---|---|---|
| 国内オーディオブック市場 | 2024年度 約260億円 | 日本能率協会総合研究所。**2020年時点の予測ベースで実績値ではない** |
| audiobook.jp 会員数 | 300万人突破（2024年2月） | 8割以上が「学習」目的 |
| ポッドキャスト月間利用率 | 全年代18.2%、15〜19歳は40.5% | オトナル×朝日新聞、2026年2月公表 |
| 国内電子書籍市場 | 2025年度 6,846億円 | **うちコミック87.7%＝TTSが原理的に効かない** |

日本のオーディオブック市場は米国（2025年実売$2.43B）の**1/10以下**。ElevenLabs/Speechify が本気で取りに来るには小さすぎるが、それ自体がデメリットでもある。

## 5. ビジネスとしての妥当性 — 率直な評価

### 先行者の実績

| 企業 | ユーザー/評価額 | 売上 |
|---|---|---|
| **Speechify** | 5,000万ユーザー（公称）、評価額$100〜120M | **ARR 約$17.6M**（2025年） |
| **ElevenLabs** | 評価額**$11B**（2026年2月、Series D $500M） | ARR $500M（2026年4月） |

**Speechify の数字が最も重要。** 5,000万ユーザーに対して ARR $17.6M。仮に月$10なら有料会員約15万人＝**課金率0.3%程度**。この領域の先行者かつ最大手ですら、8年やってユニコーンに届いていない。

さらに創業者自身が「**AIトークン費用が人件費を上回る**」「Speechifyは1日1,300本の広告を回している」と公言。つまりこれは**大量の有料広告でDLを買い、薄い課金率で回収する広告オペレーション勝負**であり、プロダクトの良さ勝負ではない。個人開発者にとって致命的な情報。

ElevenLabs の $11B は Reader アプリが生んだものではなく B2B API 側の成果。しかも**TTS原価が自社なのでReaderを無料〜格安でばら撒く余力がある**。

### 撤退・失敗事例

| サービス | 結末 |
|---|---|
| **Umano** | 人力ナレーション記事音声化の草分け。消滅 |
| **Audm** | 2020年にNYTが買収 → その後クローズ |
| **NYT Audio アプリ** | 2023年5月ローンチ → **同年10月に単体アプリ終了**、News本体アプリのタブに統合 |
| **Curio** | €7.6M調達 → 記事ナレーションから**AIニュースアンカーへピボット** |
| **Pocket** | 2025年7月終了。読み上げ機能を持ったうえでの終了 |
| **Instapaper** | Pinterest → **チームが買い戻し**（2018）、以降縮小均衡で自立 |

**共通パターン:**
- **人力ナレーション型は全滅。** 原価が月$10前後のサブスクに合わない。
- **メディア企業が自前でやっても持たない。** NYTは資金・コンテンツ・ブランド全部あってスタンドアロンが無理だった。「音声は独立アプリではなく既存プロダクトの一機能」というのが大手の到達点。
- **買い戻し／縮小均衡が生き残りの形。** 数十億円規模のexitはこのカテゴリでほぼ起きていない。

### 課金の実態

RevenueCat "State of Subscription Apps 2025" より:
- DL→有料転換率: **ハードペイウォール中央値 12.11% vs フリーミアム 2.18%**（約5.5倍差）
- トライアル→有料: 低価格帯 47.8% vs 高価格帯 28.4%
- Media & Entertainment カテゴリのトライアル→有料: 43.8%

**無料枠を厚くすると死ぬ。** しかしこの領域で無料枠を厚くしたくなるのは「まず聴いてもらわないと価値が伝わらない」から。ここがジレンマ。

### 市場規模データの注意

- 米国オーディオブック実売（APA集計）: 2024年 $2.2B（+13%）→ **2025年 $2.43B（+9%）と減速**
- Grand View Research の世界市場推計は**同社内で「2030年$35B」と「2033年$58.5B」という整合しない数字**を出している

米国だけで$2.43B、北米シェア39.6%なら世界は約$6.1Bのはずが、GVRは世界$11B（2025）としている。**CAGR 20%超の推計を事業計画の根拠にしてはいけない。** 信じるべきはAPAの実売集計（減速中）の方。

### 最大のレバーはキャッシュ設計

ElevenLabs v3 キャッシュなし（$36,000/月）と オンデバイス（$50/月）で **700倍**の差。

- **記事が共有されるサービス**（ニュースアグリゲーター、キュレーション）なら合成済み音声のCDNキャッシュだけで**10分の1**になり、クラウドTTSが現実的になる。
- **「ユーザーが任意のURLを投げる」設計はキャッシュヒット率が上がらず**、クラウドTTS単価がそのまま効く。

### ローカルOSS TTS の地雷3つ

1. **Piper に日本語がない。** 「軽量ローカルTTS = Piper」で設計に入れると詰む。日本語が必要なら **Kokoro-82M**（Apache-2.0）が実質唯一の汎用候補。
2. **Style-BERT-VITS2 は AGPL-3.0。** 日本語品質は最高評価だが、**サーバーサイドで使うと改変ソース公開義務が発生し得る**（ネットワーク配信条項）。商用クローズドソースのバックエンドに置くのは法務レビュー必須。
3. **VOICEVOX はキャラクターごとに別の利用規約。** エンジン/コアはMIT（0.16以降）だが、**生成音声の利用は各キャラの規約に従う**必要がある。「VOICEVOXは商用OK」は不正確。

### 日本語前処理は自前で持つ必要がある

どのエンジンを選んでも必須で、エンジン乗り換え時の資産になる:

1. **数字・単位の読み下し**（「2026年8月16日」「約1.5km」「第3位」）
2. **英字・略語のカタカナ事前変換**（「API」「Wi-Fi」）
3. **固有名詞のアクセント辞書** — pyopenjtalk（MIT）のユーザー辞書機構、SSMLの `<phoneme>`、Googleの音素指定。**クラウドTTSでもアプリ側辞書は必須**
4. **同形異義語**（「行った」「市場」）— MeCab/Sudachi、または**LLMに読み仮名を振らせて事前正規化**。記事1本4,000文字なら安価なモデルで $0.01未満で、TTSコストより一桁小さい
5. **記号・装飾の除去**（Markdown記法、絵文字、「▼」「※」）

| ツール | ライセンス | 備考 |
|---|---|---|
| **Trafilatura** | Apache 2.0（v1.8.0以前はGPLv3+） | ベンチマークで最良評価。ただし**日本語/CJKの明示的な言及がドキュメントにない** |
| **Mozilla Readability** | Apache 2.0 | Firefoxリーダーモードの実装。デファクト |
| **Postlight Parser**（旧Mercury） | Apache 2.0 | **Mercuryから改名済み**。古い情報に注意 |

- **抽出ミスがそのまま音声品質になる。** テキストなら「変なナビが混ざってる」で済むが、音声では**「メニュー、ホーム、ニュース、スポーツ…」を延々と読み上げる**致命的なUX破綻になる。音声用に追加のヒューリスティックフィルタ（短行連続の除去、リンク密度の高いブロックの除去）が必要。
- **Paywall は技術問題ではなく法務問題。** 回避手段の実装は推奨しない。
- **JSレンダリング必須のSPAメディアが増加**しており、これがサーバーコストの隠れた主因になる。

## 7. 法務 — 設計を決定づける制約（日本法）

> 以下は調査メモであり法的助言ではない。実装前に弁護士の確認を推奨する。

### 核心となる条文

- **著作権法24条（口述権）**: 「公に」口述する権利。**2条7項**により録音物の再生も含む。ユーザーが自分のイヤホンで聴くだけなら「公に」に当たらず、口述権の問題は生じない。
- **30条（私的使用のための複製）**: 2要件は①個人的・家庭内の範囲で使用する目的、②**「その使用する者が複製する」**。
- **23条（公衆送信権）**: 「公衆」＝不特定または特定多数。**送信の相手が1人ずつでも、不特定の者に向けたサービスなら公衆送信に当たる。**
- **49条**: 私的目的で複製したものを後に頒布・公衆送信すればみなし侵害。

### 決定的な判例

**自炊代行事件（知財高判 平成26年10月22日）** — 業者が複製主体であり「複製された電子ファイルを私的使用する者は利用者であることから『その使用する者が複製する』ということはできない」として30条1項の適用を否定、複製権侵害を認定。**「ユーザーが押したボタンで動くだけ」という説明は通らなかった。**

→ **サーバー側でスクレイピング＋サーバー側でTTS生成は、この構造そのもの。最も危険な設計。**

**読売新聞 v. デジタルアライアンス（知財高判 平成17年10月6日）** — 記事見出しの著作物性を否定しつつ、無断で反復継続して利用する行為は社会的に許容される限度を超え**不法行為を構成する**として損害賠償を認容。**「著作物性がないから自由」は通用しない。**

### 使えない言い訳

| 主張 | なぜ通らないか |
|---|---|
| 「情報解析（30条の4）だから適法」 | **読み上げはまさに享受目的**。文化庁の整理では享受目的が1つでも併存すれば適用外 |
| 「非営利無料だから38条1項で口述OK」 | **38条1項は上演・演奏・上映・口述に限られ、ネット配信＝公衆送信には適用されない** |
| 「アクセシビリティ目的だから37条3項」 | 主体は政令（施行令2条）の要件を満たし**文化庁長官の個別指定を受けた者**に限られる。一般の営利アプリ事業者は該当しない |
| 「限定公開のプライベートRSSだから私的」 | URLを知っている人だけ＝非公開ではない。不特定の者に向けたサービスは公衆送信 |

### 新聞社の規約

読売新聞オンラインは2024年2月適用の規約改定で、①データマイニング・テキストマイニング等の言語解析、②**クローリング、スクレイピング等の自動化された手段による収集・抽出・加工・解析・蓄積**、③生成AIへの学習・開発 を明示的に禁止。情報解析目的の利用には別途ライセンス契約が必要と明記。

### 設計の対比

**✅ 比較的安全**

1. **端末内完結** — ユーザーが自分の端末で開いたページを、**OS標準TTS**で読み上げる。音声ファイルを作らず**ストリーム再生のみ**にすれば複製すら最小化できる。
2. **ブラウザ拡張／リーダーモード型** — 取得はユーザー自身の通常のブラウジング。自動巡回・一括取得をしない。
3. **RSS／公式APIの範囲内** — サイトが公式に配信している範囲だけを扱う。
4. **公式に音声化が許諾されたコンテンツ** — Audible、audiobook.jp、青空文庫等のパブリックドメイン、CCライセンス作品。
5. **共有機能を作らない** — 生成音声はエクスポート不可、URLも発行しない。

**🔴 危険**

1. **サーバー側スクレイピング＋サーバー側TTS生成**（自炊代行事件の構造そのもの）
2. **なろう／カクヨムの本文を機械的に取得**（規約が禁止例として名指し）
3. **プライベートRSS／共有リンクで音声を配信**（公衆送信権）
4. **生成音声をサーバーに蓄積してライブラリ化**
5. **新聞社サイトのクローリング**
6. **ペイウォール／DRM回避**（30条1項2号で私的使用の例外からも外れる）

## 8. 安全性 — 出発点の問いへの回答

### 歩きスマホの実害

**東京消防庁（救急搬送データ）:**

| 項目 | 数値 |
|---|---|
| 歩きスマホ等に係る事故での救急搬送 | **171人**（令和3〜7年の5年間） |
| うち2025年 | **43人**（直近5年で最多） |
| 年代別最多 | **20歳代 31人**（10代ではない） |
| 事故種別 | ころぶ71人（4割超）／落ちる47人／ぶつかる46人 |
| 発生場所 | 約7割が道路・交通施設 |

**規制:** 歩きスマホを規制する国の法律は存在せず罰則もない。大和市（2020年7月、全国初）、足立区、荒川区、池田市などの自治体条例のみで、**いずれも罰則なし**。大和市の調査では歩行者の約12%が歩きスマホをしていた。

### 「耳で聴く」は本当に安全か

**画面注視よりは安全だが、無条件に安全ではない。** リスクの質が「視覚遮断」から「聴覚遮断＋認知負荷」に置き換わる。

**Lichenstein et al. (2012), Injury Prevention** — ヘッドホン装着歩行者の事故116件:
- **70%が死亡**
- 衝突車両の**55%が列車**
- **29%のケースで車両側が警笛等を鳴らしていた**（＝鳴らしても届かなかった）

> 留意: これは症例集積であり分母がないため相対リスクは算出されていない。「ヘッドホンで死亡率が◯倍」という主張はこの研究からは導けない。ただし**リスクが特に高いのは踏切・駅ホーム**という具体的文脈は読み取れる。

**Inattentional deafness（非注意性難聴）** — Molloy et al., J Neurosci 2015: 視覚課題の負荷が高いとき**聴覚への脳反応が有意に低下**する。**サイレンやクラクションは通るが、自転車のベルやエンジン音のような小さい音は聞こえなくなる。**

含意は両義的:
- 「画面を見る」→「耳で聴く」への移行は、**視覚チャンネルを周囲監視に解放する**点で明確にプラス。
- 一方、聴覚コンテンツに深く没入すれば逆方向のリスクが起こる。**「難しい内容を集中して聴く」は歩きながらには向かない。**

### デバイス選択

- **ANC（ノイズキャンセリング）は歩行中の感覚遮断リスクを最大化する。** 歩行中は必ずOFF。
- **外音取り込み（Transparency）モード**を常時ON。
- **骨伝導／オープンイヤー型**は状況認識の維持という点で最良。ただし「骨伝導だから耳に優しい」は誤りで、**大音量による難聴リスクは空気伝導と同じ**（蝸牛の有毛細胞は経路を区別できない）。

### 法規制はこの方向性に追い風

- **自転車のイヤホン**: 警察庁ルールブック（2025年9月公開）が「**片耳のみの装着、オープンイヤー型、骨伝導型など耳を完全には塞がないものは、安全な運転に必要な音又は声が聞こえる限りにおいて違反にならない**」と明記。規制対象は**イヤホンの種類ではなく「聞こえる状態か」**。
- **自転車のながらスマホ**（2024年11月1日改正道交法施行）: **6月以下の拘禁刑又は10万円以下の罰金**、交通の危険を生じさせた場合は1年以下の懲役又は30万円以下の罰金。ただし規制されるのは「**画面の注視**」と「手持ち通話」であり、**ハンズフリーの音声聴取は明示的に除外**されている。
- **自動車**: 道交法に直接の禁止条文はないが、各都道府県規則（東京都道路交通規則第8条(5)等）で「安全な運転に必要な音が聞こえない状態」を禁止。普通車で反則金6,000円。

### 「聴く読書」の理解度

**Clinton-Lisell (2022) メタ分析**（46研究、N=4,687、Review of Educational Research）:
- **全体として読解と聴解の理解度に有意差なし**（g = 0.07, p = .23）
- ただし**読みが自己ペースの場合は読みが有利**（実験者ペースでは差が消える）
- **推論的理解・全般的理解では読みが有利、逐語的理解では差なし**

UC Berkeley の fMRI 研究（2019）では、読むときと聴くときの**脳の意味マップはほぼ同一**。

**再生速度:** UCLA (2022) は 1x/1.5x/2x/2.5x を比較し、**2xまでほぼ横ばい、2.5xで明確に低下**。ただし研究間で結論が割れており、内容依存（密度の高い内容は高速化に不向き）。**8〜10時間程度の訓練で高速聴取に順応する**という知見もある。

### 実務的な推奨

1. **開放型デバイスを選ぶ。** オープンイヤー／骨伝導が第一選択。カナル型なら外音取り込み常時ON、**歩行中はANCを絶対にOFF**。
2. **片耳運用を歩行時の基本にする。** 警察庁が自転車について示した基準は歩行時の自主基準としても使える。
3. **音量は「自転車のベルが聞こえる」を基準に。** サイレンは通っても小さい音が先に聞こえなくなる。
4. **踏切・駅ホーム・横断歩道では聴取を止める。** 他の場所と質的にリスクが違う。
5. **画面操作を完全にゼロにする。** 曲送りのために画面を見るなら安全上の利得はほぼ消える。
6. **歩きながらは「要旨を掴む」用途に限る。** 細部の正確な想起が要るコンテンツは着席時に回す。
7. **速度は2.0倍を上限に。**

### プロダクトが備えるべき安全機能

**必須**
1. **完全ハンズフリー操作** — 再生/一時停止、前後シーク、章ジャンプ、速度変更、ブックマークの全てをイヤホンのタップと音声コマンドで。**画面を見に行かせた時点で設計目的を裏切る。**
2. **移動検知に連動した歩行中モード** — 歩行中は情報密度を落とした要約レイヤーを再生（inattentional deafness に直接根拠がある）。自転車・車両検知時は通知を抑制。
3. **ANC強制解除／外音取り込み強制**
4. **絶対に画面を要求しない再生継続** — ログイン切れ、次エピソード選択などで画面タップを強制するフローを排除。これは安全機能である。
5. **音量の安全上限**

**避けるべきマーケティング**

「歩きながら読書を」と訴求してはいけない。歩行中に高負荷の聴取を促すことは、視覚負荷を聴覚負荷に置き換えるだけで安全にならない。訴求すべきは「**画面を見なくて済む**」であって「歩きながら集中できる」ではない。

## 9. ユーザーの不満から見える最大の穴

### 最強の裏付けが取れた穴：再生が止まる

**独立5ソースで同一症状が報告されている:**
- Android で画面オフ後**きっかり4分**で音声停止（ken107/read-aloud #512）
- 一部Android端末で画面オフ中にTTSが読めない（readest #2099）
- iOS 16.5 でバックグラウンドのTTSが動かない（Apple Developer Forums 732576）
- OSやタスクキラーによるプロセスkill（Hyperionics サポートフォーラム）
- Gemini アプリでもバックグラウンド移行と同時にTTS即停止（Google AI Developers Forum）

原因は Android のバッテリ最適化によるプロセスkill、および**「音楽再生である」というメディアヒントをOSに渡していない**こと。

**これは AI音質競争とは無関係の実装品質の問題**（MediaSession / foreground service / 堅牢なレジューム）。大手は音質と課金に投資しており、ここを取りこぼしている。**歩きながら聴く用途を直撃する致命傷であり、明確な差別化点。**

### 課金の誠実さが差別化要素になる

Speechify / NaturalReader / ElevenLabs の**3社とも、低評価の主因は音質ではなく課金導線**:
- Speechify: 「解約し忘れて年額を丸ごと請求された」「無料プランに直接登録する手段がなくクレカ登録を伴うトライアルを強制される」
- ElevenLabs: 音質は93%ポジティブなのにレビュー分析記事のタイトルが **"Great AI, Shady Pricing"**
- NaturalReader: Trustpilot系で1.4/5、「支払い情報を削除するページが存在しない」

**負けているのは技術ではなく信用。**

### アクセシビリティ領域は勝者不在

**Voice Dream Reader サブスク移行炎上（2024年）** — 買収元が$79/年のサブスクへ移行し、かつ**旧買い切り版を実質的に無効化**しようとした。ユーザー層は視覚障害・ディスレクシア等の当事者中心。価格より「旧版を使えなくすること」が争点になり、Appleの介入を求める公開書簡まで出て、**最終的に撤回**。

**この領域で最も踏んではいけない地雷。** 同時に、ElevenLabs Reader も AppleVis で「Frustration with ElevenLabs reader and perceived lack of interest」（関心を示してくれないことへの苛立ち）というスレッドタイトルで批判されており、**音質最高でもVoiceOverバグ放置なら見捨てられる**。新規参入 Readify が公開フィードバックを募集中で、勝者不在の状態。

## 10. 参入するなら

### 明確な地雷

1. **「Speechifyの代替を安く作る」** — 最悪手。1日1,300本の広告を回す相手にユーザー獲得単価で勝てない。勝ってもARR $17.6Mの天井。
2. **無制限読み上げ＋定額サブスク** — TTS原価が変動費なのでヘビーユーザーに殺される。
3. **人力ナレーション** — Umano・Audm・Curio が全滅済み。
4. **「あとで読む」＋読み上げの汎用アプリ** — Pocketが読み上げ機能を持ったうえで終了した領域。
5. **フリーミアムで無料枠を厚くする** — DL→有料の中央値が2.18%。
6. **調査会社のCAGR 20%超を事業計画の根拠にする**
7. **英語圏でのグローバル勝負** — ElevenLabs が $11B で降りてきている。正面衝突は不可能。

### 現実的な勝ち筋

1. **超ニッチ × 高単価 × ハードペイウォール** — 一般消費者ではなく、大量の長文を読まねばならない特定職種（法務、医療、研究、士業）。**月$30〜50を払う人を数百人見つける方が、月$5のユーザーを10万人集めるより現実的。**
2. **日本語という参入障壁を逆手に取る** — グローバルプレイヤーが最後まで手を抜く部分（縦書き、ルビ、固有名詞の読み、アクセント）。ただし市場が小さいこと自体はデメリット。
3. **読み上げを主機能ではなく既存ワークフローの一部にする** — NYTがAudioアプリを畳んでNewsアプリのタブにした事実。単体の読み上げアプリはプロダクトとして自立しない。
4. **原価をユーザー負担にする** — BYOK（ユーザー自身のTTS APIキー）、従量課金・クレジット制。定額無制限を捨てればTTS原価リスクが消える。**個人開発なら「小さくても潰れない」の方が価値が高い。**
5. **ワンショット買い切り／ローカル完結** — サーバー原価ゼロ、サブスク解約リスクゼロ。市場は狭いが誰にも殺されない。

### 特に有望に見える具体案（法務クリアが前提）

**A. ラノベ／Web小説の共有読み辞書**
最大の不満（固有名詞の誤読）に対し、誰も作業を共有可能にしていない。作品IDに紐づくクラウド読み辞書＋**作者本人が正しい読みを登録できる導線**。本文を持たず「読み方のメタデータ」だけを扱えば、なろうの本文取得禁止規約にも抵触しない。既存の読み上げアプリのアドオンとして成立しうる。

**B. 「絶対に止まらない」再生エンジン**
独立5ソースで裏付けの取れた穴。「画面を消して30分歩いても止まらない」を測定可能な約束として掲げる。位置は秒単位で永続化し、アプリがkillされても復帰する。地味だが最も確実な差別化。

**C. 自分専用のRSS→ポッドキャスト化パイプライン（自分用に自作）**
n8n の公式テンプレートが複数あり、**Kokoro TTS をローカルで回せば音声生成コストをほぼゼロ**にできる。プライベートRSSにすれば Pocket Casts / Overcast の既存機能（自動オフラインDL、キュー、倍速、CarPlay、再生位置同期）がそのまま使える。地下鉄など圏外区間のある通勤には事前ダウンロード前提の設計が決定的。
**ただし他人に配布した瞬間に公衆送信権の問題が生じるため、自分専用に留めること。**

### 一言で

**この領域は「市場がない」のではなく、「市場はあるが、その市場から金を取る手段が壊れている」。** ユーザー数は取れるが売上にならず、原価は変動費で、上限価格はOS標準機能と$11B企業のフリーミアムに押さえられている。この構造を承知のうえで、「小さく高く売る」か「他のプロダクトの機能として乗せる」以外の入り方は、個人・小規模には推奨できない。

## 11. 調査の限界（正直な記録）

本調査には以下の制約があった。数値を意思決定に使う前に一次ソースでの再確認を推奨する。

- **WebFetch がegressプロキシでほぼ全ドメインをブロック**され、多くの一次資料（公式価格ページ、条文原文、規約原文、論文本文、App Store/Trustpilotのレビュー原文）に直接アクセスできなかった。大半は検索結果の要約経由。
- **Reddit はクローラ拒否ドメイン**のため、r/tts、r/ereader、r/LightNovels、r/Blind 等の一次スレッドに到達できていない。
- **複数のエージェントが検索予算上限（200件）に到達**した。
